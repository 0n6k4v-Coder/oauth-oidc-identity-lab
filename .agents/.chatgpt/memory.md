# Memory

## Lecture Writing Framework

1. You Must Deep Research the Latest Official Standards, Specifications, RFCs, and Other Authoritative Sources Relevant to the Topic Before Writing the Lecture.

2. You Must Carefully Evaluate the Sources for Recency and Status.
   - Identify the latest applicable standards and specifications.
   - Check whether older standards have been superseded, deprecated, obsoleted, amended, or updated.
   - Do not rely on outdated guidance when a newer authoritative standard exists.
   - The lecture must reflect the current state of the standard, while clearly distinguishing older versions when historical context is necessary.

3. You Must Attach All Authoritative Standards and Official References Used to Develop the Lecture.
   - References must point to the actual sources used.
   - Prefer primary sources such as official standards bodies, RFCs, specifications, and official documentation.
   - Do not cite sources merely because they are related to the topic; cite sources that materially informed the lecture.

4. The Lecture Must Have a Precise, Well-Organized Learning Structure.
   - Organize the lecture in a logical learning progression.
   - Each section must have a clear purpose and contribute to the learning objective.
   - Introduce concepts in the order required to understand them.
   - Avoid jumping between concepts, responsibilities, protocol layers, or levels of abstraction without a clear reason.
   - The structure should be designed around the knowledge being taught, not around an arbitrary number of sections.
   - You may modify, merge, remove, or add sections whenever doing so produces a clearer and more accurate learning progression.

5. The Lecture Must Be Focused and Proportionate to Its Learning Objective.
   - Explain concepts precisely enough to establish correct understanding.
   - Do not unnecessarily expand explanations, create excessive sub-items, or introduce concepts that belong to later lectures.
   - Do not generate details merely to make the lecture appear comprehensive.
   - Include only the level of detail that is appropriate for the lecture's position in the overall learning path.
   - When a concept is intentionally deferred to another lecture, keep the explanation sufficient for context without prematurely teaching the later topic.

6. Every Lecture Must Preserve Technical Accuracy and Conceptual Boundaries.
   - Do not mix concepts that belong to different protocol layers or responsibilities.
   - Clearly distinguish normative requirements from explanatory interpretation.
   - Do not invent behavior, requirements, terminology, or protocol rules that are not supported by authoritative sources.
   - When the standard permits multiple approaches, explain the relevant distinction rather than presenting one implementation pattern as universally required.

7. The Final Lecture Should Be Designed as Part of a Complete Learning Path.
   - Consider what the learner should already know before this lecture.
   - Consider what this lecture must establish for the next lectures.
   - Avoid unnecessary duplication with previous or future lectures.
   - Each lecture should build naturally toward complete understanding of the subject.

8. The Lecture Must Use Presentation Formats That Match the Content.
   - Use precise bullet points when they improve readability, scanning, comprehension, or memorization.
   - Use tables when the content naturally involves comparison, classification, mapping, parameters, roles, properties, differences, or structured relationships.
   - Use ASCII diagrams when a protocol flow, architecture, sequence, relationship, request/response interaction, or system boundary is easier to understand visually.
   - Use normal prose when prose is the clearest way to explain a concept.
   - Do not force bullets, tables, ASCII diagrams, or any other format onto content that does not naturally benefit from them.
   - Choose the presentation format based on the learning objective and the nature of the content, not according to a fixed pattern.
   - Multiple presentation formats may be combined within the same lecture when each format provides a distinct learning benefit.
